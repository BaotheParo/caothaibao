The Challenge

Spike traffic triggered severe thread contention and duplicate resource-intensive text processing queries, causing spikes in database latency and CPU throttling.

task_alt

Engineering Solution

Engineered a thread-safe Request Coalescing mechanism utilizing ConcurrentHashMap and CompletableFuture, deduplicating concurrent in-flight requests for identical payloads. Offloaded computationally heavy transformations to asynchronous worker threads via Spring @Async.

The Challenge

Complex rule-based candidate sorting and quota allocations resulted in catastrophic database deadlocks and severe N+1 query bottlenecks during mass admission batches.

task_alt

Engineering Solution

Eliminated transaction deadlocks by enforcing deterministic lexicographical sorting before batch execution via JdbcTemplate.batchUpdate(). Replaced iterative database round-trips with an in-memory caching model achieving O(1) criteria lookups, slashing multi-minute jobs to sub-second execution.

JdbcTemplate • Deadlock-Free Order
@Transactional
public void executeDeadlockFreeAdmissionBatch(List<AdmissionDecision> decisions) {
// Enforce deterministic row-lock order to eliminate circular wait
var sorted = decisions.stream()
.sorted(Comparator.comparing(AdmissionDecision::getCandidateId))
.toList();
// High-throughput bulk write via Hikari connection pool
jdbcTemplate.batchUpdate(SQL_UPDATE_STATUS, sorted, 1000, (ps, d) -> {
ps.setString(1, d.getStatus());
ps.setLong(2, d.getCandidateId());
});
}
